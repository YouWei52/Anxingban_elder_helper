# 后端部署指南

## 环境要求

- **操作系统**: Linux (推荐 Ubuntu 20.04+)
- **Python**: 3.10+
- **MySQL**: 8.0+
- **内存**: 最少 1GB
- **磁盘**: 最少 10GB

## 环境变量配置

### 必填变量

| 变量名 | 说明 | 示例 |
|--------|------|------|
| `DATABASE_URL` | 数据库连接字符串 | `mysql+pymysql://user:pass@host:3306/db` |
| `TOKEN_SECRET` | JWT密钥（32位+） | `your-super-secret-key-here-32chars` |

### 可选变量

| 变量名 | 默认值 | 说明 |
| -------- | -------- | ------ |
| `APP_NAME` | 安行伴 | 应用名称 |
| `ENVIRONMENT` | production | 运行环境 |
| `LOG_LEVEL` | INFO | 日志级别 |
| `LOG_FILE` | logs/app.log | 日志文件路径 |
| `LOG_MAX_BYTES` | 104857600 | 日志文件最大大小(100MB) |
| `LOG_BACKUP_COUNT` | 10 | 日志备份文件数量 |
| `SMS_PROVIDER` | mock | 短信服务商 |
| `PILOT_CITY` | Chongqing | 试点城市 |
| `GUIDE_SCOPE` | knowledge_limited | 导游范围 |
| `WECHAT_WEBHOOK_URL` | (空) | 企业微信WebHook地址 |

## 端口配置

- **默认端口**: 8000
- **健康检查**: `/health`
- **API文档**: `/docs`

可通过环境变量 `PORT` 修改端口号。

## 部署方式

### 方式1: Docker部署（推荐）

#### 1. 创建环境变量文件

```bash
# 复制模板
cp .env.example .env

# 编辑配置
nano .env
```

`.env` 示例：

```bash
# 数据库配置
DATABASE_URL=mysql+pymysql://anxingban:YOUR_PASSWORD@47.237.188.77:3306/anxingban_prod?charset=utf8mb4

# 安全密钥
TOKEN_SECRET=your-production-secret-key-minimum-32-characters-long

# 日志配置
LOG_LEVEL=INFO
LOG_FILE=/app/logs/app.log
LOG_MAX_BYTES=104857600
LOG_BACKUP_COUNT=10

# 应用配置
APP_NAME=安行伴-生产环境
ENVIRONMENT=production

# 短信配置
SMS_PROVIDER=aliyun

# 微信配置
WECHAT_WEBHOOK_URL=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_KEY
```

#### 2. 构建并启动

```bash
# 构建镜像
docker-compose build

# 启动服务
docker-compose up -d

# 查看日志
docker-compose logs -f backend

# 停止服务
docker-compose down
```

#### 3. 验证部署

```bash
# 健康检查
curl http://localhost:8000/health

# 预期响应
{
  "status": "healthy",
  "database": "connected",
  "version": "1.0.0"
}
```

### 方式2: 直接部署

#### 1. 安装依赖

```bash
# 创建虚拟环境
python3 -m venv .venv
source .venv/bin/activate

# 安装依赖
pip install -r requirements.txt
```

#### 2. 配置环境变量

```bash
# 方式A: 导出环境变量
export DATABASE_URL="mysql+pymysql://user:pass@host:3306/db?charset=utf8mb4"
export TOKEN_SECRET="your-secret-key-at-least-32-characters"
export LOG_LEVEL="INFO"
export LOG_FILE="logs/app.log"

# 方式B: 使用.env文件
cp .env.example .env
nano .env
```

#### 3. 创建日志目录

```bash
mkdir -p logs
chmod 755 logs
```

#### 4. 初始化数据库

```bash
# 数据库会在首次启动时自动创建表
# 确保MySQL数据库已创建：
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS anxingban_prod CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

#### 5. 启动服务

```bash
# 开发模式（带热重载）
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 生产模式（多进程）
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4

# 使用Gunicorn（更稳定）
gunicorn app.main:app --workers 4 --worker-class uvicorn.workers.UvicornWorker --bind 0.0.0.0:8000
```

#### 6. 配置系统服务（可选）

创建 `/etc/systemd/system/anxingban.service`:

```ini
[Unit]
Description=安行伴后端服务
After=network.target mysql.service

[Service]
Type=notify
User=www-data
WorkingDirectory=/opt/anxingban
Environment="DATABASE_URL=mysql+pymysql://user:pass@localhost:3306/db"
Environment="TOKEN_SECRET=your-secret-key"
Environment="LOG_LEVEL=INFO"
Environment="LOG_FILE=/var/log/anxingban/app.log"
ExecStart=/opt/anxingban/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable anxingban
sudo systemctl start anxingban
sudo systemctl status anxingban
```

## 日志管理

### 日志文件位置

- **Docker部署**: `/app/logs/app.log` (容器内)
  - 挂载到宿主机: `./logs/app.log`
- **直接部署**: `logs/app.log` (相对路径)

### 日志格式

```
2026-08-25 10:30:45,123 - app.main - INFO - Application started
2026-08-25 10:30:46,234 - app.modules.profile - INFO - [REQUEST] POST /api/profiles - {"parent_name": "张***"}
2026-08-25 10:30:46,345 - app.modules.profile - INFO - [RESPONSE] 200 - {"code": 200, "message": "success"} - 0.111s
2026-08-25 10:30:47,456 - app.modules.profile - ERROR - [ERROR] ERR_DATABASE_ERROR - Database connection failed
```

### 日志轮转

- **触发条件**: 文件大小超过 `LOG_MAX_BYTES` (默认100MB)
- **备份数量**: `LOG_BACKUP_COUNT` (默认10个)
- **命名规则**: `app.log.1`, `app.log.2`, ...

### 查看日志

```bash
# 实时查看
tail -f logs/app.log

# 查看最近100行
tail -n 100 logs/app.log

# 搜索错误
grep ERROR logs/app.log

# 统计错误数量
grep -c ERROR logs/app.log

# 查看特定时间段
grep "2026-08-25 10:" logs/app.log
```

```bash

```

## 故障排查

### 问题1: 服务无法启动

```bash
# 检查端口占用
lsof -i :8000

# 检查日志
tail -n 50 logs/app.log

# 检查环境变量
env | grep DATABASE_URL
```

### 问题2: 数据库连接失败

```bash
# 测试数据库连接
mysql -h host -u user -p database

# 检查配置
echo $DATABASE_URL

# 查看详细错误
python -c "from app.database import engine; engine.connect()"
```

### 问题3: 日志文件过大

```bash
# 手动轮转
mv logs/app.log logs/app.log.$(date +%Y%m%d)
touch logs/app.log

# 清理旧日志
find logs/ -name "app.log.*" -mtime +30 -delete
```

## 安全建议

### 1. 数据库安全

- 使用强密码
- 限制远程访问IP
- 定期备份数据

### 2. API安全

- 生产环境使用HTTPS
- 配置防火墙规则
- 限制请求频率

### 3. 日志安全

- 不记录敏感信息
- 定期清理旧日志
- 限制日志文件权限

```bash
chmod 640 logs/app.log
chown www-data:www-data logs/app.log
```

## 性能调优

### 1. 进程数量

根据CPU核心数调整workers：

```bash
# 推荐公式: (CPU核心数 * 2) + 1
uvicorn app.main:app --workers 9  # 4核CPU
```

### 2. 数据库连接池

在 `config.py` 中调整：

```python
pool_size=10          # 基础连接数
max_overflow=20       # 最大溢出连接数
```

### 3. 日志级别

生产环境建议使用 `INFO` 或 `WARNING`：

```bash
export LOG_LEVEL=WARNING  # 只记录警告和错误
```
